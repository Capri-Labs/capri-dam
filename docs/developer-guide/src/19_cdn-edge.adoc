[[section-cdn-edge]]
= CDN and Edge Operations

CDN support is abstracted behind adapter classes and coordinated through
`CdnManager`.

== Providers and adapter contract

[cols="1,3", options="header"]
|===
| Adapter | Notes
| `CdnAdapters::FastlyAdapter` | Supports invalidation, surrogate keys, and signed delivery patterns.
| `CdnAdapters::CloudflareAdapter` | Supports zone-oriented purge operations.
| Akamai-style support | The configuration model anticipates additional provider implementations even where the adapter class is not yet primary in this repo snapshot.
|===

== Core capabilities

* HMAC URL signing for protected delivery URLs
* cache invalidation by object or surrogate key
* metadata sync to edge provider APIs
* provider-specific purge semantics hidden behind `CdnManager`

== Endpoints

[cols="1,2,3", options="header"]
|===
| Method | Path | Description
| `GET/PUT` | `/api/v1/cdn_configurations` | Read/update CDN settings.
| `POST` | `/api/v1/edge_operations/purge` | Purge objects or surrogate keys.
| `POST` | `/api/v1/edge_operations/sign_url` | Generate signed delivery URL.
| `POST` | `/api/v1/edge_operations/sync_metadata` | Push metadata refresh to edge.
|===

== Image optimizer format allow-list (AVIF delivery)

`Api::V1::CdnConfigurationsController` stores an admin-configurable
`image_optimizer_formats` array on `CdnConfiguration#settings` (an encrypted
JSON column, so no migration is required to add new keys). This lets an admin
declare which output formats the Fastly Image Optimizer is permitted to serve
for a given CDN configuration.

* `FASTLY_IMAGE_OPTIMIZER_FORMATS = %w[webp avif]` is the current allow-list
  constant on the controller.
* `#update` rejects any value outside the allow-list with `422 Unprocessable
  Entity` and a descriptive `errors` array (e.g.
  `"Unsupported image optimizer format(s): gif. Supported: webp, avif."`).
* `#format_config` (used by `#index`) does **not** mask
  `image_optimizer_formats` the way it masks real secrets (API tokens, keys) —
  it's plain configuration, not sensitive data. This is controlled via the
  `NON_SECRET_SETTINGS_KEYS` constant.
* The Admin → System Status → Storage & Edge tab
  (`StorageOperationsTab.jsx`) was previously a **simulated** UI (it used a
  `setTimeout` to fake load/save and never called a real endpoint). It now
  performs real `GET`/`PUT` calls against `/api/v1/cdn_configurations` and
  renders WebP/AVIF checkboxes bound to `image_optimizer_formats`.

IMPORTANT: The allow-list now governs *two* things, not one: what an edge CDN
is permitted to serve, and what this application will produce at request time
(below). One switch, one behaviour, whether or not a CDN sits in front.

== Request-time format negotiation

`Api::V1::AssetsController#serve_local` re-encodes an image on the way out when
— and only when — three parties agree. Each can veto:

[cols="1,3"]
|===
| Party | Veto

| The administrator | The format must appear in `image_optimizer_formats` on the
  *active* `CdnConfiguration`. With no active configuration nothing is
  transcoded, so the feature stays off until somebody turns it on.
| The client | The `Accept` header must name `image/avif` or `image/webp`
  explicitly. A wildcard (`image/*`, `*/*`) is not evidence — every browser
  sends one regardless of what it can decode, and a browser sent a format it
  cannot decode shows a *broken* image, not a larger one.
| The encoder | The result must actually be smaller. See below.
|===

`ImageDelivery::FormatNegotiator` decides the format; `ImageDelivery::Derivative`
produces and caches the bytes. Preference is AVIF before WebP.

An explicit `?output=avif` bypasses the `Accept` check (a build pipeline
fetching AVIF is not a browser and need not pretend to be one) but is still
subject to the administrator's allow-list. The parameter is `output`, not
`format`, because Rails already uses `format` for the routing extension —
`/assets/local/x.png` would otherwise arrive as a request for PNG.

=== Only photographs are re-encoded

`TRANSCODABLE_SOURCE_TYPES` is JPEG and PNG. SVG is excluded because
re-encoding a vector destroys the reason it is one; GIF because it may be
animated, and a single-frame AVIF would silently truncate it to its first
frame; AVIF/WebP because they are already optimal.

=== A derivative that is not smaller is thrown away

AVIF is usually much smaller, but not always: on small images the format's
fixed overhead can exceed what it saves, and re-encoding an already-lean JPEG
can produce something *bigger*. `Derivative` compares the encode against the
source and discards it if it did not pay for itself. The point of the feature
is fewer bytes, not newer formats.

Every failure path returns `nil` rather than raising — this runs inline on an
image request, so a missing delegate or a corrupt source must degrade to the
original, never turn a working image into a 500. Sources above
`MAX_SOURCE_BYTES` (25 MB) are served as-is rather than transcoded on a request
thread.

=== Caching and invalidation

Derivatives are content-addressed files under `storage/dam/.derivatives`, keyed
on a digest of the source's path, size and mtime plus the encode settings. They
are deliberately *not* `renditions` rows: a delivery derivative is disposable,
has no independent identity, and giving it a database row would mean inventing
a storage backend for it and keeping row and file in step on every re-upload.
The digest gets invalidation for free — re-uploading changes the source's
size/mtime, which changes the key, so the stale derivative is simply never
asked for again.

Writes go to a unique temp file and are moved into place, so two concurrent
requests for the same image cannot serve each other a half-written file.

=== Two HTTP details that matter

*`Vary: Accept` is set on every response from the endpoint*, including 304s and
untranscoded originals. The chosen format depends on `Accept`, so a shared
cache keyed only on the URL would happily hand an AVIF to a client that cannot
decode it. This is the classic way to break content negotiation.

*The ETag is computed over the bytes actually sent*, not over the source. A
shared ETag would let a client holding the JPEG revalidate into a `304` and
never receive the AVIF at all.

=== Bug fix: `CdnConfiguration#settings` encryption was completely broken

While wiring the Edge CDN tab to the real API, saving *any*
`CdnConfiguration` (not just the new format field) was found to always raise:

[source]
----
NoMethodError: undefined method 'type=' for an instance of ActiveRecord::Encryption::Context
----

Root cause: `encrypts :settings, type: :json` is **not a valid option** on
this Rails version — `type:` silently corrupts the encryption context. This
was already known and worked around in `SystemConnector` (see its own code
comment), but `CdnConfiguration` still used the broken pattern, and the
existing model/request specs all stubbed `CdnConfiguration` with
`instance_double`/`allow(...).to receive(:save)`, so the real persistence
path was never actually exercised — the bug shipped silently. Fixed by
declaring the attribute's JSON cast type first, then encrypting with no
extra options:

[source,ruby]
----
attribute :settings, :json
encrypts :settings
----

`spec/models/cdn_configuration_spec.rb` now includes real (non-stubbed)
persistence tests: round-tripping a settings hash through encryption, and
asserting the raw database column never contains plaintext.

  `cdnEdge.*` translation keys across all 10 locales.

  vetoes: no active CDN configuration, a format the administrator left off, a
  client that advertises only a wildcard; plus SVG/GIF/video exclusions and the
  `?output=` override still obeying the allow-list.
* `spec/services/image_delivery/derivative_spec.rb` — a real AVIF/WebP is
  produced at the source's dimensions, the cache is reused and re-keyed when the
  source changes, an encode that is not smaller is discarded and cached, and a
  corrupt source, missing file, oversized source or failing encoder all return
  `nil` instead of raising.
* `spec/requests/api/v1/asset_image_delivery_request_spec.rb` — end to end:
  real AVIF magic bytes in the body, `Vary: Accept` on transcoded *and*
  untranscoded responses, a distinct ETag per format, 304 still working, and
  the WebP fallback for a client that cannot decode AVIF.
